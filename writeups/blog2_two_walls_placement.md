# blog2 · 两堵墙与放置规则 —— 这套系统最值钱的产出，被实测打脸了四次

> English version of this blog: `blog2_two_walls_placement_en.md` (translation — where the two disagree, **the Chinese text wins**).

> **写作红线（四篇共用，贴在页眉）**：
> ① **一阶量与二阶量两列并报**："误差 <1%" 不许单独成句（方法论 22：L2 差 11.6x 时 KL 差 303x，gc=0→1 那一格两列方向相反）。
> ② **质量只报相对量 + 必附参照行**：换成 8 选 2 fp32 稠密 MoE 本身就值 KL 1.897e-01(bs=32) / 8.854e-02(bs=128) ⇒ 比引擎最狠那档贵 **668x / 871x**。
> ③ **显存必须写明峰值 MB 还是稳态 MB**：gc=5 峰值两档同为 186.1MB，稳态才是 169.3(fp32) vs 109.8(bf16)。
> ④ **三方交换只用 P0-④a 两张归档**；每个数字指回一张用户自跑的判决表。
> ⑤ **配对段 Δ 只认【配对可用】✓ 行**；✗ 行的 Δ 是噪声底。
> ⑥ **跨进程双峰格给区间不给单点**（A bs=128 `gc=3 bf16` = 1.35 / 1.74ms）。

## 0. 一句话

**放置规则（哪几个专家进 GPU）是这套东西真正的产出，kernel 和图只是让规则能说出口的代价。**
而它的历史就是四次被实测打脸：每次打脸的原因都一样 —— **规则少了一条腿**。
这一篇给**四条腿**各自的定价表：CPU 侧两堵墙、GPU 侧一堵墙、质量侧一条新腿，以及 §8 那条把前三条逼到墙角的第四条腿 —— **单价**。

模型只有一句（所有表都按它付钱）：

```
每帧延迟 ≈ max(CPU 腿, GPU 腿) + 固定串行主机开销
```

**"重叠"这件事本身是有价格的，而且价格是正的**：P0-② 用 `overlap=False`（同一个模型对象上翻布尔、
输出逐位相同、互差 0.000000000）把它量成 **16/16 格为正 +8.5%~+67.6%**，A 放对下随 bs 单调涨
（gemm +8.5→+39.5、swiglu +11.6→+67.6，依次 bs=1/4/32/128）。这是那条"X 倍加速"的**唯一合法来源**。

## 1. CPU 侧的两堵墙，和一个交叉点

| 墙 | 定价 | 谁在这堵墙上 | 怎么证出来的 |
|---|---|---|---|
| **字节墙** | 每个**有流量**的专家整趟读 2MB ÷ 42GB/s = **49us/专家**（真形状 swiglu 2.53MB ⇒ **63us**） | 配置 A（放对，每专家约 1/5 个 slot） | 纯 CPU 卡尺实测 45GB/s 档；改算术无效 |
| **算力墙** | 每 slot 2M 次 int8 MAC ÷ **288 GMAC/s** = **7us/slot**（与权重重扫几趟**无关**） | 配置 C（放错，每专家 29/26/4 个 slot） | 单核 **1 趟 55.4 vs 8 趟 54.2 GMAC/s** —— 重扫的权重在 L2/L3 里不要钱 |
| **交叉点** | 每专家约 **5 个 slot** | | 两式相等 |

两个必须记住的结论：

1. **"CPU kernel 是带宽 bound"这句话是半句**（T8 被 T14 修正了一半）：它只对"每专家 slot 很少"的配置成立。
   本机无 AVX-VNNI（`vpdpbusd`=0），AVX2 `maddubs` 的内层指令数决定算力墙，**换循环顺序（减少重扫）实测无效**。
2. **CPU 腿的真成本是 `max(字节墙, 算力墙)`，而规则只记了字节墙** ⇒ 配置 C 被系统性低估 ⇒ 这条待办（T15）
   **已冻结进 P2**（本机常数级别的活，写在"局限"里，不动手）。

**掉队税（同一台机器上第三种墙，人的墙）**：帧内主线程要做 graph replay / D2H 入队，它和绑在 core0 的
OMP 线程 0 **同核** ⇒ 线程 0 半速，而 `static,32` 是**开跑前就把 2048 行平摊** ⇒ 整个并行区等它一个。

| 调度 | 独占 min/p50 | 挂 1 个抢核 | 挂 2 个抢核 |
|---|---|---|---|
| `static,32`（历史默认） | 478 / 559 us | **839 / 905**（← 帧内量到的 811us 就是它） | 862 / 865 |
| `guided`（新默认，逐位等价） | 453 / 505 | **569 / 590（−32%）** | 652 / 706（−24%） |

端到端（11 轮配对，L2 p50）：**A −6.8%、C −12.4%**；挂 1 个抢核时 C **−17.5%（0/11 轮更慢）**。
🚨 关键读法：**端到端的"无抢核"≠卡尺的"无抢核"** —— 帧内主线程本身就是那个抢核者，
所以这一刀不需要外挂进程也成立，外挂进程只是把它放大给看。**结论可迁移："预先平摊"在有抢核的机器上会被掉队者决定长度。**

## 2. GPU 侧那堵墙：按权重字节付钱，标定值必须实测

| 标定项 | 填什么 | 填错的代价 |
|---|---|---|
| GPU skinny GEMM 有效带宽 | **250GB/s**（实测） | 🚨 填 360 峰值 ⇒ 高估 GPU 成本 ⇒ **不敢抬 gc ⇒ 少赚 12%** |
| CPU 侧有效带宽 | **42GB/s**（DDR4 实测） | 同上，方向相反 |
| L3 预算 | 0.75×12MB ⇒ **最多 3 个常驻**（真形状 int8 2.53MB/专家） | 8 个专家全常驻 = 20.2MB ⇒ 每帧多付 5×63us |

这堵墙最贵的一次现身是乙-2 的那笔悬案：swiglu 相对 gemm 有一笔 **+0.22~0.30ms、与 CPU 腿 slot 数完全无关**的
成本，A bs=1（CPU 腿一个字节都不读）也照付。乙-2b 把它拆开（用户独立复现，头行 loadavg **0.16** = 台账里最干净的一次）：

| 配置 | 形状 | GPU 半边 | CPU 半边 | max(半,半) | 端到端 |
|---|---|---|---|---|---|
| A（CPU 腿 **0 slot**） | gemm | 0.177 | 0.001 | 0.177 | — |
| A | swiglu | 0.471 | 0.001 | 0.471 | ΔGPU **+0.294** / ΔCPU +0.162（被重叠藏住）/ Δ端到端 **+0.298** |

根因：**热专家权重存成 fp32**，每帧要读 125.8MB ⇒ **415us / 126MB = 303GB/s，已经是这张卡的读上限**。
⇒ 字节 bound 的东西只能靠少读字节 —— 这就是 blog3 的降精那一刀，也是 blog2 的第四条腿。

## 3. 放置规则 v1 → v2：缺的从来不是系数，是另一半成本

| 版本 | 规则 | 它回答的问题 | 它答不了什么 |
|---|---|---|---|
| **v1** | 「CPU 侧被摸到的权重 ≤ **0.5×L3** 就停手」 | CPU 侧还挤不挤 | 没有 bs 项、没给 GPU 半边定价 ⇒ 恒定选 gc=5 |
| **v2** | `gc = argmin_gc max(CPU 半边, GPU 半边)` + **平手规则** | 再买一个 GPU 专家划不划算 | 没给 dtype、流量/质量定价（⇒ P1） |

两个设计决定值得单独说：

- **取 max 不是相加**：两条腿本来就重叠（§0 那个模型）。相加 ⇒ 双重收费 ⇒ 规则系统性保守。
- **平手规则是第二半，不是细节**：bs=16/A 的 gc=2 与 gc=3 模型只差 **1us（6%）**，而实测差 **12.8%**
  ⇒ 这个尺度上模型**没有分辨力**。所以 8% 带内先取 CPU 字节更少者、再取更小 gc —— **八格才全部选中实测最优或落在噪声带内**。

**为什么"改系数"救不了 v1**（T13 实测）：要让 v1 给 A 选 gc=3，就得把预算压到 4MB 以下，
那样 C 会被推到 gc=5（实测比最优慢 2.6%）。**同一条系数不可能同时修好两个配置 —— 缺的是另一半成本。**

### 3.1 规则 vs 实测最优（这是规则的全部账单）

**P0-② gc 扫描（玩具形状，8 格，独占口径）**：规则**恒定 gc=5**，实测最优在 **{0,1,2,3,7} 之间移动**，
**8/8 格偏贵 +16.4%~+95.0%**（最狠：swiglu bs=1 A 最优 gc=1 = **0.279ms** vs 规则 gc=5 = **0.545ms**，贵 95.0%）。
**方向也会错**：C 放错 + bs≥32 实测最优 **gc=7**（比规则更激进），bs=1 实测最优 **gc=0/1**（比规则保守）。

**P0-④a 三方交换（真权重，放对；"贵" = 规则档 p50 相对实测最优）**：

| bs | fp32：规则 / 实测最优 | bf16：规则（规则真值）/ 实测最优 | 放错档的欠给 |
|---|---|---|---|
| 1 | 0 / 0（🚨规则输入退化：bs=1 只有 **2 个 slot**） | 1（真值 2）/ 3 | — |
| 32 | **5 / 5 = 正中** | 5（真值 6）/ 7 ⇒ 贵 **+11.4%** | C 档 fp32 **+10.7%**（bf16 侧跨进程不稳，不单点引用） |
| 128 | **5 / 5 = 正中** | 5（真值 6）/ 7 ⇒ 贵 **+27.0%** | C 档 fp32 **+101.5% / +106.5%**（两个进程） |

读法：v2 的两条腿在 fp32、bs≥32 上**已经正中**；bf16 把 GPU 半边打折后规则**确实敢给更大 gc**（真值 5→6），
但三次都还差一档 —— **这就是规则 v2 缺的那半个价（blog3 的降精）**；而放错档欠给 +101~106% 说明
**规则完全不看命中分布**（下一条腿）。

## 4. 规则缺的第一条腿：dtype 定价（实测已到手，规则差一档）

④a 把 `gpu_weight_bytes` 真的接到 dtype 上（闸门：`规则选gc` 列 fp32→bf16 从 5→6，同时 idx 差全 0
⇒ 降精没漏进路由）。**规则敢给更大 gc，但不敢给到实测最优**：因为规则给 GPU 半边记的是**字节价**，
而实测里 GPU 半边只有在成为**关键路径**时才真的兑现（见 blog3 的 −8.1% vs −52.8% 对照）。
**这一条腿已在 P1 清单上，数据背书已够，缺的是规则里的第二次标定。**

## 5. 规则缺的第二条腿：质量与流量（这条是 P0-③ 掉出来的新结论）

**放错不只慢，还贵质量**（同 bs 同 gc 的 C/A KL 比）：

| bs | gc=3 | gc=5 | gc=7 | top-1 有没有真掉 |
|---|---|---|---|---|
| 32 | **11.6x** | **20.3x** | 5.7x | gc=5：**100.00 → 96.88** |
| 128 | **10.3x** | **21.8x** | **13.8x** | gc=3：100.00 → 98.44 |

根因很机械：放错让更多 slot 落回 int8 腿（gc=5 bs=128：CPU 腿 **22 → 177 个 slot**）。
**质量随 gc 单调降，但对 CPU 腿 slot 数亚线性**：bs=128 从 256 slot → 1 slot，slot 涨 **256x** 而 KL 只涨 **81x**
⇒ **质量由最热那一两个 slot 有没有进 GPU 主导**，之后迅速变平。

⇒ **放置规则 v2 从此有第二条腿：以前只按延迟定价，现在质量也按 CPU 腿 slot 数定价。**
但**规则不能吃 KL 本身**（§blog1 红线①：gc=0→1 那一格 L2 与 KL 方向相反）——
**能吃的是命中分布（slot 数 × 命中%）**，KL 只当验收。
> 🚨**回溯更正（P1-②c 实测，见 §8）**：这句话【方向对、量纲错】—— 命中分布只是**代理**，不是账。
> 在人造漂移段，「覆盖流量%」与实测 KL 的段内 Spearman 塌到 **+0.60**，而「CPU 腿专家单价之和」仍是 **+1.00**；
> 按覆盖最优选的成员集在 drift 段比按单价选的**贵 1.60 倍** KL。真正的账是「谁让 int8 多付 KL」，
> 命中只是它在本机不漂时留下的影子。旧文按原样保留，不静默改写（方法论：错了要留痕）。
而命中分布在这台机器的真源上是**量出来的天然偏斜**：命中 `[42.3, 13.2, 17.7, 6.8, 1.4, 12.6, 6.0, 0.1]`、
**最热/最冷 = 433x**、最冷专家 **0.1%** —— 这就是"动态热专家放置"最直接的动机（P1 第一优先）。

## 6. 规则缺的第三条腿：零流量也要付钱（稠密税）

P0-④a 给这笔钱第一次标了价：bs=1 放对上 `gc=3 → gc=8` 两档**流量完全相同**（GPU 腿都 2 slot、CPU 腿都 0 slot），
p50 fp32 **0.257 → 0.434ms**、bf16 **0.215 → 0.317ms** ⇒ **每多驻一个零流量专家付 35us(fp32) / 20us(bf16)**，
多驻 5 个要多付 **69% / 47% 的帧时买 0 个命中**。
⇒ 规则按"命中% × 权重字节"记账是对的，但**实现必须真的按流量付钱**；今天的稠密写法让规则的账和实测对不上。
（同一格的降精 Δ 是 **−16.1%（7/7 轮）** —— 数值逐位不动、时间照付，那正是**可回收的上界探针**，见方法论 25。）

**最后一句纪律**（方法论 14，两次自伤换来的）：**分账表（诊断用）的实测半边不能直接当规则的输入。**
孤立紧循环量的是 warm cache 稳态，在缓存边界上会系统性低估真帧成本；规则吃的是**标定带宽 + 平手规则**。
看到诊断表打印"模型不够"，先做两件事：拿改动前的备份重跑一遍（排回归）、去查规则**实际**吃的是什么数（排口径混淆）。

## 8. 规则缺的第四条腿：单价（P1-②c/②d，实测已到手）

§5 那条腿说「质量按 **CPU 腿 slot 数 × 命中%** 定价」。P1-②c 把它按住又量了一遍，结论是：
**命中% 只是代理，真账本是每个专家自己的 int8 误差单价。**

### 8.1 价怎么量：一张 8-float 的表，0 个自由参数

`u_e` = 只把专家 e 放进 CPU 腿（`gc=E−1`、钉死最后一槽、其余全在 GPU）测到的 KL；`kappa_e = u_e / 命中_e` = 专家本体误差。
readme 段节选（`2e7f1cb2`：22 个引擎 / 66 格 / 196s / 27 个归档锚点）：

| eid | 命中% | `u_e` = KL(只有它在 CPU 腿) | `kappa_e` | 相对最便宜 |
|---|---|---|---|---|
| 0 | 42.3 | 1.8054e-05 | 4.269e-05 | 227x |
| 2 | 17.7 | 2.7506e-05 | 1.556e-04 | 346x |
| 3 | 6.8 | 3.9594e-06 | 5.792e-05 | 50x |
| 4 | 1.4 | 7.9542e-08 | 5.818e-06 | 1x（最便宜） |
| 7 | 0.1 | 3.4673e-07 | **3.550e-04 = 全表最贵的本体** | 4.4x |

**最热的那两个（0、2）确实贵，但「贵」和「热」不是同一个序**：只有 **0.1%** 流量的 eid7，本体误差是全表最贵的；
`kappa` 谱跨 **61x**（3.550e-04 / 5.818e-06），而 §5 那根杆吃的是**命中谱**（433x）。

三根 **0 自由参数**的杆对打，比的是「预测 KL ÷ 实测 KL」（1.0 = 中靶）：

| 杆（怎么预测一个成员集的 KL） | 段内 Spearman：readme / input.txt / drift | 跨段 23 格比值 |
|---|---|---|
| M0 覆盖流量%（= §5 那条腿） | +0.98 / +0.98 / 🚨**+0.60** | 几何均值 1.03，范围 **0.15~1.86**（22/23 在 [0.5,2]） |
| **M1 单价 `Σu_e`** | **+1.00 / +1.00 / +1.00**（n=9/10/6） | 几何均值 **1.01**，范围 **0.92~1.11**，**23/23** 在 [0.5,2] |
| M2 台账旧口径 L2rel% | +0.98 / +1.00 / +0.71 | — |

两个端点也对得上（比相关系数硬）：**全 CPU 实测 KL ÷ `Σu_e` = 0.902 / 1.070 / 0.920** —— int8 误差在 KL 域基本可加，
所以「价」不是拟合出来的，是**量出来的加法**。最狠的一格：CPU 腿只剩 `{7}`（0.1% 流量），
M0 只给出实测的 **0.15 倍（低估 6.7x）** —— **计数型机制量的误差随「是谁留在 CPU 腿」系统偏移，调系数救不回来**。
这就是缺腿，不是缺标定。

### 8.2 判据从【热】换成【单价】之后：3/3 段落到实测 KL 最小的编员集

P1-②d 只把判据里「比较的量」从命中占比换成 `u_e`，骨架（容量 / 冷却 / 一进一出 / 迁移机制）一字未动：
**11 策略 × 3 阶段 = 33 行同格**，闸门②（迁移后引擎 vs 按运行时 `slot2eid` 重建 = 逐位同）全过、闸门③（CUDA Graph 不重录）33/33。

| 段 | 价最优编员集（`price_*` 末态，实测 KL） | 覆盖最优编员集（原来那档「地板」） | 谁便宜 |
|---|---|---|---|
| readme | `{0,2,3}` = 9.370e-06 | `{0,1,2}` = 9.711e-06 | 覆盖最优**贵 3.6%**，而它的覆盖流量 73.1% > 66.8% |
| input.txt | `{0,2,5}` = 6.145e-06 | 同一个集 | 打平 |
| drift | `{0,2,3}` = 1.301e-05 | `{0,5,6}` = 2.079e-05 | 🚨覆盖最优**贵 1.60 倍** |

⇒ 三段的价最优，都正好是**该段实测过的 gc=3 编员集里 KL 最小的那一个**（3/3，含人造漂移段）。
⇒ **旧文档里那个叫「地板」的档位得改名为【覆盖最优档】**：它是按命中直方图选的成员，**不是 KL 最小化器** ——
   `KL/地板 < 1` 是**合法读数**（§7 与判读提示⑧ 早就给它留了这句话，现在有了机制解释）。
⇒ 起跑编员 / 上帝视角 `{0,2,1}` **三段都不是价最优**：价 gap = **8.6% / 44.1% / 21.7%** —— 静态放得再好也还剩钱在桌上。

**价签与兑现**（这一条才是这一刀真正的自证；复核轮 `27f8c744`）：
`{0,2,5} → {0,2,3}` 那次迁移，判据开火前打印**预测降 8.0%**，实测 `1.414e-05 → 1.301e-05` = **降 7.99%**；
`price_cal@input.txt` 的价 gap 列印 **30.3%**，拿 r2 归档实测算可赚 **30.43%**（8.833e-06 → 6.145e-06）；
价最优那些格的 `M1 ÷ 实测` = **0.92 / 1.01 / 1.01**。
⇒ `thr_rel = 5%`（「预测降幅低于一次迁移的价签就不该动手」；本机单次迁移实测 13.8~22.8ms = **2.6~4.4 帧**）
   从一句口号变成**逐格可核的数值判据**。

### 8.3 跨域怎么办：一次否证 + 一个便宜得多的替代

- **否证**：`kappa_e` 的段间 Spearman 均值只有 **+0.16**（−0.38 / +0.76 / +0.10）⇒ **换语料不能查同一张 kappa 表**；
  同一格的 `u_e` 排序稳得多（+0.62 / +0.88 / +0.81）⇒ **该查的是 `u_e`，不是裸 kappa**。
- **顺手省掉一刀**：`price_cal`（查标定段的 `u_e` 表）与 `price_hit`（`kappa_e ×` 在线窗内占比重定价）
  **末态成员集与 KL 逐位相同** ⇒ 在线重定价**不改决策** ⇒ 原计划的「影子探针」（P1-②e）**不开**。
- 剩下的缺口只在换语料那一格：`price_cal@input.txt` 的 KL/A = 0.85，而用本段真价的 oracle 是 0.59（还差 30.3%）。
  替代方案便宜得多：**离线按域各备一份 8-float 价表**，不写在线探针。

> **一句话**：「谁更热」是代理，「谁让 int8 多付 KL」才是账；而这张账本在本机**只有 8 个 float**。

## 9. 规则缺的第五条腿：迁移的价签 —— 量完之后，第四条腿的收益归零成「开局一次性放置」

§8 把判据从「谁更热」换成「谁让 int8 多付 KL」，并且 3/3 段落到实测 KL 最小的编员集（`27f8c744` 那一刀还
留下预测 **8.0%** ↔ 实测 **7.99%** 的对账）。这一节讲它的代价那一侧：**换一次要付多少钱**，
以及一个不太好看的收尾 —— **在计表口径下，这些钱一次都没真的付过。**

### 9.1 价签三刀：每一刀都推翻上一刀的口径

| 刀 | 归档 | 怎么量 | 结论 | 落点 |
|---|---|---|---|---|
| 一 | `6eabc1de` | 翻转窗墙钟差 ÷ 帧长尺子 | sync 价签 **19.30 帧/次** × 帧长 **3.911ms** = **75.5ms/次**；而 flip 自己的 p50 只有 **15855µs**（≈4.1 帧）⇒ **只占 1/5** | 挂账（押 G1 打脸）：钱不在 flip 里，但那 4/5 是什么没答上 |
| 二 | `0e305a89` | 把窗切成 C(负对照)/H(恢复窗)/**M(稳态)**/P(残留) | sync `C 0.30 / H 21.76 / **M 64.80** / P −6.92 / T 79.94` ⇒ **M/T = 81%** | **I2** ⇒ 🚨**表 3 那张墙钟价签口径作废**：它把「翻转态的稳态放置惩罚」整笔记成了切换成本；`thr_rel` 不许按它重标定 |
| 三 | `22ff0967` | 每轮加发两段【整段都在翻转态】的 basef/swapf ⇒ `once=(tag+tagf)/2` 把稳态项**在设计上抵消** | sync **once_main = 4.89 帧/次 = 19.9ms**；async_staged once = 1.09 帧 ⇒ **ratio_once = 0.22**；稳态惩罚单列 `sync 4.645 / async_direct 5.230 / async_staged 4.436 ms/帧` | **J2**（押 J2 兑现）⇒ 旧表一张不动，但从此「一次性」与「稳态」必须分开写 |

第三刀的自洽检查是关键：抵消只在「每帧惩罚是常数」时成立，所以把两把尺都归一到 **ms/帧** 再比 ——
自洽差 sync **9%** / async_direct 6% / async_staged 7%（<50%）⇒ 抵消成立，`19.9ms` 这个数才有资格用。

**这条腿现在进规则了**：开关点判据是 `thr_rel = 5%`，它要的是「换一次付几帧」= **一次性价签**；
稳态项在真决策里**符号是反的**（换过去通常更好），所以不能拿来当门槛。

### 9.2 然后：收益那一侧被读成了「开局一次性放置」

`P1-②附2附`（`d9d54f5b`，n=25）跑的是**决策计数器**而不是延迟列，所以它不怕双峰，结论也最硬：

> **计表轮逐臂 0 次决策**（A1/A2/A3/C1/H1/H2 全部 0次/0ms），全程物理迁移只有 H1 2次/26ms、H2 1次/13ms。

⇒ 之前 dyn 表里那句「dyn 省 20%~27%」发生在**计表轮之外**（起跑放置那一下），
在计表口径下只能读成 **【开局一次性放置】**：按 §8 的单价判据选好常驻集，**然后一帧都不搬**。
这不是「动态放置没用」的证据（见下），而是「**它没被考核过**」的证据。
