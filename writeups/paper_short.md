# 异构 MoE 的单价判据放置：一台 12 核台式机上的度量、价签与一个负结果

> 小论文（自洽可读版）。深链：判据与价签的推导见 `blog2_two_walls_placement.md` §8/§9，
> 测量纪律与"这把尺为什么不合格"见 `blog1_measurement.md` §9，索引与复现见 `README.md` §4/§8。
> **每个数字后面括号里是归档件 md5 前 8 位**，全部在 `results/`，全部由人自跑并贴全文（机器状态在头行）。

## 摘要

在一个 8 专家 / top-2 的 SwiGLU MoE 上，把 3 个专家常驻 GPU、其余以 **int8 权重常驻 CPU 并按路由取用**，
在 i5-10400（6C/12T、双通道 DDR4、实测 42GB/s、12MB L3、无 AVX-VNNI）+ RTX3060 上可以做到：

1. **放置判据用"单价"而不是"热度"**：`u_e` = 只把专家 e 放进 CPU 腿时测到的 KL。0 个自由参数，
   在 3/3 个语料段上选出的常驻集**就是实测 KL 最小的那个**（`2e7f1cb2`, `3ce6836d`）。
2. **CPU 侧的墙有两堵、交叉点要实测**：字节墙（权重字节 / 42GB/s）与算力墙（AVX2 maddubs 上限）在
   ≈5 个常驻 CPU 专家处交叉；GPU 侧按权重字节付钱（`ebf87c3b`, `0bdd9f58`）。
3. **零流量专家也付钱（稠密税），且可以修掉**：分批后每帧 **35.8→3.6us(fp32) / 20.6→1.8us(bf16)**；
   bs=1 decode 因此比同配置的**纯 CPU 路**还快 **34.1%**（`64436f8a`）。
4. **负结果（本文最主要的一条）**：**动态放置（跟随流量漂移搬运专家）至今没有被有效考核过一次**。
   四棵预设判决树全部死在"尺子前置"。最终定性原因 r4 叫**臂身份固定效应 ≈8%**、r5 改判为**每实例一次性偏移**
   （`σ_inst≈1.6%`，逐进程最坏格极差 4.73~7.42%）：同一份配置的引擎实例之间存在与真值无关的稳定偏移，
   它**不吃发数、不吃估计量、不吃建臂顺序、也不吃进程数** ⇒ 本机对 **≲5~7% 的臂间差不可分辨**
   （`48499173`, `1f69a7cb`）。"**再买一层重复就能判**"这条退路已**离线核算判死**：`k=3` 台常驻能把前置买到
   `P(绿)≈98%`，但落点判不动（问句 `T` 的 `±1σ` 仍是判定点间距的 **3.9x**，判动需 `k≈47` = 329 台常驻
   = RSS 57.9GB，物理不可能），且毙点**不是工作集**而是"跨实例配对 + 分母放大"这对结构。

🚨**本文不含"自适应放置有效"这一类主张。**目前可引用的收益全部来自**开局一次性放置**。

## 1. 被测系统与主张边界

- 模型：SmolLM 形状（`D=576, N=1536`），取第 8 层 MLP 的 8 个专家做 8 选 2，权重为真权重、形状为真形状。
- **裁判** = 同架构 8 选 2 的 **fp32 稠密 MoE**，不是原模型。⇒ 质量只报**相对量**，且必须附参照行：
  "把稠密 FFN 换成 MoE 本身"就贵 **668x / 871x / 1585x**（三个 bs 档，`fba72657`, `13f8740c`）——
  在这个参照系下，引擎各档之间的 KL 差只能读"gc 之间 / dtype 之间"。
- 显存一律写明**峰值 / 稳态**两列（高水位与稳态差 200MB 量级，`5bb8a840`）。
- 所有常数本机专属（42GB/s、250GB/s、12MB L3、6C/12T、桌面会抢核）。**可迁移的是测法与结论，不是数字。**

## 2. 度量方法（本文的"装置"）

| 部件 | 做法 | 它挡住的事故 |
|---|---|---|
| 同进程轮转配对 | 同一格的所有被测档在**一个进程内**交替跑，正序 + 反序各一轮 | 绝对值的跨进程漂移被读成收益 |
| 聚合 | **p50 / 块和**；🚨**禁 min-of-N** | `ROUNDS=2` 造出假 27%、T8 假 −16% |
| 入库门槛 | 头行 `loadavg < 0.8`、`ROUNDS ≥ 7`、逐轮 σ% | 桌面抢核轮入库 |
| 空对照组 | 2~3 台**配置逐字相同、从不开火**的臂 | ——（本文 §6 的主角） |
| 正对照组 | 一台**已知很慢**的臂（成员集故意选错） | "尺子坏了"被读成"没有效应" |
| 上限锚（oracle） | 探针知道每块正确答案、零反应延迟，但**付同一笔迁移成本** | 把"追得慢"与"上限本来就没有"混成一句 |
| 闸门 ⓪~⑨ | 逐位等价、slot↔专家映射连查、图不重录、计数器和路由一致、放置无关性、静态档零迁移…… | 抓到 **4 个真 bug** |
| **预设判决树** | 前置条件 + 问句 + 事前预测，**跑前写死在 docstring**，代码自动求值并打印落点 | 事后挑一个能解释的门槛 |

**关键纪律**：前置条件（尺子合不合格）与问句（科学问题）**分开**。前置不过 ⇒ 问句不许读，落点只能是"挂账"。

## 3. 三条腿的证据

### 3.1 CPU 侧两堵墙

单个 CPU 专家的边际成本 = `max(权重字节/42GB/s, 算力)`，两堵墙在 **≈5 个 slot/专家**处交叉（`ebf87c3b`）。
**`3.07x` 的确切口径**【该轮跑在演示形状 `D=1024/N=2048`：gemm 单矩阵 2MB/专家、SwiGLU 三矩阵 6MB/专家】：
拿 C 列 `bs=32→128` 两点求斜率 ⇒ gemm `8.2us/slot`、swiglu `25.2us/slot` ⇒ **每 slot 边际成本比 3.07x**
⇒ 三矩阵**没有隐藏串行**，如实付 3 倍钱。🚨它既不是整帧比值、也不是"真形状 vs 演示形状"：
整帧 `swiglu/gemm` 随 bs 走 —— 轮转口径 C 列 bs=1/4/32/128 = **2.25/2.79/2.89/3.02**（`ebf87c3b`）、
solo 口径 = **2.241/2.310/2.690/3.018**（`3840ec53`）⇒ **≈3x 只在 bs=128 成立、低 bs 真值 2.2~2.4**。
真形状（SmolLM `D=576/N=1536`，w1/w3/w2 共 **2.53MB**/专家）的字节墙是 **63us/专家**，不是 6MB 档的 147us。

### 3.2 GPU 侧按权重字节付钱

GPU 半边热专家权重从 fp32 降到 bf16：端到端 **−15.4%(gemm) / −33.9%(swiglu)**（`ee301770`），
但**标定值必须实测**：裸 mm 的等效带宽与端到端兑现率不是一回事（`dtrate` 探针）。

### 3.3 稠密税与 decode

零流量专家每帧照付 **35.8us(fp32) / 20.6us(bf16)**（`a1dabef9` 结论④）；
traffic-sparse 分批把它压到 **3.6 / 1.8us**（÷9.9 / ÷11.4），于是 bs=1 最优 **0.184ms** < 同份纯 CPU **0.279ms**
= **−34.1%** ⇒ "decode 阶段只能退回纯 CPU"这条直觉作废（`64436f8a`）。
🚨分批只在 bs=1 落地：bs=128 上 traffic 路大亏 **+238.3%**（`25746271`）。

## 4. 单价判据（本文的可迁移产出）

**定义** `u_e` = 只把专家 e 放进 CPU 腿（`gc = E−1`）时测到的 KL；`kappa_e = u_e / 命中率_e`。
**判据** 常驻集 = 在容量预算下最小化 `Σ_{e∈CPU} 命中_e × u_e`；换人门槛 `thr_rel = 5%`。
**代价** 0 个自由参数、一张 **8 个 float** 的离线表。

| 检验 | 结果 | 归档 |
|---|---|---|
| 段内排序稳定性 | Spearman **三段全 +1.00**（n=9/10/6） | `2e7f1cb2` |
| 跨段排序稳定性 | 23 格 **0.92~1.11** | `2e7f1cb2` |
| 可加性（端点可验） | 预测/实测 = **0.902 / 1.070 / 0.920** | `2e7f1cb2` |
| **选出的常驻集是不是实测最优** | **3/3 段：是** | `3ce6836d` |
| 对比旧判据（覆盖/热度） | 覆盖最优在 drift 段**贵 1.60 倍** | `3ce6836d` |
| 一次可核的预测 | 预测降 **8.0%** ↔ 实测 **7.99%** | `27f8c744` |
| 跨域 | `kappa_e` 段间 Spearman 仅 **+0.16**，`u_e` **+0.62/+0.88/+0.81** ⇒ 查 `u_e` 表，**按域各备一份** | `2e7f1cb2` |

⇒ "谁更热"是代理；"谁让 int8 多付 KL"才是账。而这张账本在本机只有 8 个 float。

## 5. 迁移价签三刀（口径每一刀都推翻上一刀）

| 刀 | 量法 | 结论 | 落点 |
|---|---|---|---|
| 一（`6eabc1de`） | 翻转窗墙钟差 ÷ 帧长 | sync **19.30 帧/次 × 3.911ms = 75.5ms**；flip 自身 p50 15855µs ≈ 4.1 帧 ⇒ **只占 1/5** | 挂账 |
| 二（`0e305a89`） | 窗切成 C/H/**M**/P 四段归因 | sync **M/T = 81%** ⇒ 钱是**翻转态的稳态放置惩罚**，不是切换本身 | **I2**：表 3 价签口径作废，`thr_rel` 不许按它重标定 |
| 三（`22ff0967`） | 加发"整段都在翻转态"的对照 ⇒ `once=(tag+tagf)/2` 在**设计上抵消**稳态项 | sync **once = 4.89 帧 = 19.9ms**；async_staged once 1.09 帧 ⇒ **ratio_once = 0.22**；稳态 **4.645 ms/帧** 单列 | **J2**（押中） |

自洽检查：两把尺都归一到 **ms/帧** 后自洽差 sync **9%**（<50%）⇒ "抵消成立"，`19.9ms` 才可用。
⇒ **`thr_rel` 要的是"换一次付几帧"（一次性），稳态项在真决策里符号是反的，不能当门槛。**

## 6. 负结果：动态放置没被考核过，以及"尺子不合格"的定量证明

### 6.1 观察：计表轮根本没开火

`d9d54f5b`（n=25）读的是**决策计数器**（不受双峰影响）：**计表轮逐臂 0 次决策**
（A1/A2/A3/C1/H1/H2 全 0次/0ms）。⇒ 此前 dyn 表里"省 20%~27%"发生在**计表轮之外**（起跑那一下），
在计表口径下只能读成 **【开局一次性放置】**。

### 6.2 装置：造一个"成员真的会漂移"的语料 + 四棵树四次挂账

| 刀 | 唯一自变量 | 落点 | 唯一红项 |
|---|---|---|---|
| r1 `c299b2b9` | 建装置（7 臂 × 3 块 × 24 帧，块间上帝成员两两不同，闸门全绿） | **K0** | 空对照 `底_pair 6.91% > TARGET=5%`；oracle 锚过星标 = [] |
| r3 `96ecadf1` | 只换尺子（★ → ★2：两簇各自过门槛且同号） | **M0 第二次** | oracle ★2 块 = []；`底_pair 4.18%` 过了但 **`底_序 16.00%`** ⇒ 门槛 32.0% |
| r4 `48499173` | 只换估计量（每块 p50 → **块和**，判据数值与装置一字不改） | **M0″ 第三次** | `底_pair **8.41%** > 5%`（n=48 ≥ N_MIN=45）⇒ 门槛 16.8% |
| r5 `1f69a7cb` | 只换复制单位（**发 → 进程**，NP=5）并把建臂顺序随机化 | **M0‴ 第四次** | c‴ 跨进程序 `底_pair` **中位 5.05%** > 5%（差 **0.05pp**）——a‴/b‴/d‴/e‴ 第一次同时绿 |

（r2 `3efbe364` 是装置作废轮：闸门⑥ 1027/1029 实为谓词漏改的**伪红**，实测硬红 0 + 瞬态 2 ⇒ 落 M0 **不追认**。）

r4 在"该起效的地方全部起效"：双峰 **11/21 → 0/21**、位次项 `底_序` **16.00% → 6.94%**、oracle 锚第一次转绿。
唯一红的仍是同一项 ⇒ 必须回答"为什么加发数和换估计量都治不了它"。r5 换了**复制单位**：`底_pair` 中位
**8.41% → 5.05%**（逐进程 `[5.81/5.03/7.42/5.05/4.73]%`）= 塌一半但**没穿过 TARGET=5%**，差 0.05pp ⇒ 第四次挂账。

### 6.3 定性：臂身份固定效应 ≈8% → **每实例一次性偏移**（本文的技术贡献）

| 证据 | 数值 | 排除了 |
|---|---|---|
| 甲 A2/A1 三块 **−8.4/−7.5/−4.1%**，每块正序轮与反序轮**同号**（正 −8.9/−8.2/−7.5，反 −7.9/−6.7/−0.6） | 同号 | 位次效应（正反序各半，同号就不可能是位次） |
| 乙 A3/A1 三块全负 **−2.6/−0.7/−1.6**（🚨逐块同号只对 A2 成立） | 两实例同向 | 单台机器的偶然 |
| 丙 净收益列 A2 **+23.0** / A3 **+4.5 ms/发** | 从不迁移的臂"白赚" | 这是真加速（物理不成立） |
| 丁 位次曲线除掉各臂**自身**跨块几何均值后只剩 **±2~3.6%** | 8% 不在位次轴上 | 位次、发数、估计量 |

⇒ 偏移在**建臂那一刻**抽定（分配器 / 页表 / 图池 / 常驻集落位一类不可控项）：
**不吃发数**（n=25→48 不动）、**不吃估计量**（p50 与块和同量级）、**同进程配对消不掉**（配对两侧是同一实例）。
⇒ **本机当前对 <≈8% 的臂间差不可分辨**，而 TARGET=5% 恰在此线以下。
处置（按跑前写死的提示）：**加发数这条路被封**；下一刀换装置 = **进程级重复 + 建臂顺序随机化**。

**r5（`1f69a7cb`）把归属改判了。** 换装置 + 随机化建臂顺序之后：`底_pair` 中位降到 5.05%（差 0.05pp 仍红），
但"偏移跟建臂位置"这一竞争假设被极差带 `[−4.32~3.89]%` 吃掉（先于 A1 `+0.02%` vs 后于 A1 `−1.13%`），
同配置实例偏移标定 **`σ_inst≈1.6%`** ⇒ 它**不绑在臂身份上**，而是**每实例一次性**（第 k 次分配出来的那块内存）：
洗牌与换进程只把偏移在实例之间**重新分配**，不改它的分布。⇒ "本机测不出 5%"这句定量结论**不变**，
但它的**成因从"可归因于身份"降级成"不可归因"** —— 这是一条更硬的负结果。

### 6.4 上限锚：有多少可吃 ≠ 你能吃到

`O1`（零反应延迟、付同一笔 flip）`GAIN = 0.6866` ⇒ 该漂移语料上放置收益**上限 31.3%**；
每帧可吃 **blk1 3.168 / blk2 3.022 ms/帧**，块长 24 帧 ⇒ **sync 回本 6.3/6.6 帧、async 1.4 帧** ⇒
**"太贵所以不该动"这个理由不成立（数学可达）**。`H1 T = 0.64`（跨轮 0.86→0.84→0.64→**0.578**，末位为 r5 跨进程中位）；r5 的 `O1 GAIN = 0.7285` ⇒ 上限 **27.2%**。
🚨这些数**全部来自前置未过的那把尺**，只作旁证，不进任何主张。

## 7. 局限

- **语料**：域外 readme 拼贴，**无 held-out ppl**；质量段只报相对量（`CORPUS=` 一到就换）。
- **裁判**：同架构 fp32 稠密 MoE，非原模型；且裁判会 **born-dirty**（一次阶段2 `|P|absmax=5.85e+19`
  把参照 KL 顶成 `2.564e+11` 而 top-1 一字未动）⇒ 个别段的质量列整段作废，根因未结清（已挂探针）。
- **样本分辨率**：top-1 分母 = 那一格 bs；bs=512 档已补跑（`13f8740c`，分辨率 **0.195pp**），bs=1 仍是单 token 硬币。
- **放置规则 v2**：默认档。bs=32 平均偏贵 **2.8%**、bs=128 **4/4 最优、0.0%**；🚨bs=1 两格 **未修**（`A fp32 +7.0%`、`C fp32 +8.1%`）。
- **噪声底 / 每实例偏移**：A 2~3%、C 8~18%；同配置实例间还有 `σ_inst≈1.6%`、最坏格极差 4.73~7.42% 的偏移
  ⇒ **任何 ≲5~7% 的"谁比谁快"都不许读**；买重复层已核算判死（判动需 `k≈47` = 329 实例 = 物理不可能）。
- **动态放置**：见 §6。异步化能把一次性价签压到 **0.22x**（`22ff0967`），但**默认仍是 sync**（改默认要用户点头）。
- **未计量项（不是负结果）**：真实文本上的自然漂移能否喂饱动态放置回路 —— **未做计量**，只做过一次零成本预检
  （只读 gate 直方图、不建臂、不计时 ⇒ 不进记录、不算任何兑现），据此**未发工单** ⇒ 本文对「真实文本上动态放置值多少」
  **不给正负任何结论**；已入库的上限锚只属于**人造漂移**且所在判决轮前置未过（只作旁证）。
- **规模与并行外推**：全部测量 = 单机单卡 + `E=8`/top-2 + 135M 形状；无多卡、无 NCCL、无专家并行（EP）的
  all-to-all、无 64+ 专家、无下游任务 ⇒ 本文是**单机异构的度量学与放置判据**，对更大规模这些数**一个字都不适用**；
  也不与任何已发布的 MoE 推理系统比数字（没跑过 = 不进表）。
- **P2 冻结**：int4、biased 打包、VNNI、寄存器分块、大 bs 调优——全部在否证清单里或有 P0 兜底才做。
