# 结项总览 —— CPU+GPU 两条腿跑 SwiGLU MoE（这台机器上每一项都按同一个模型付钱）

> English version of this index: `README_en.md` (translation — where the two disagree, **the Chinese text wins**).

> **四篇文档共用的写作红线**（写进每篇页眉，也写进 OPTLOG §4/§5.1.8）：
> ① **一阶量与二阶量两列并报**：relRMSE/L2rel 与 top-1 一致率/KL/TV 必须同时出现，"误差 <1%" 不许单独成句（方法论 22：L2 差 11.6x 时 KL 差 303x，且 gc=0→1 那一格两列方向相反）。
> ② **质量只报相对量，且必须附参照行**：把真第 8 层 MLP 换成"8 选 2 的 fp32 稠密 MoE"本身就值 KL 1.897e-01（bs=32）/ 8.854e-02（bs=128）、top-1 84.38%/86.72% ⇒ 比引擎最狠那档还贵 **668x / 871x**。本项目的任何 KL 都不许当绝对 ppl 用。
> ③ **显存必须写明是【峰值 MB】还是【稳态 MB】**：gc=5 两档 dtype 峰值同为 186.1MB，稳态才是 169.3(fp32) vs 109.8(bf16)（方法论 24）。两列不许交叉引用。
> ④ **三方交换只用 P0-④a 的两张归档**（同格同权重同裁判，闸门⓪ 已对过账）；**每个数字指回一张用户自跑的判决表**（`results/` 里有 md5/date/头行 loadavg）。
> ⑤ **配对段 Δ 只认【配对可用】✓ 行**（两腿踩 L3 均 ±10% 且更快轮 7/7 或 0/7）；✗ 行的 Δ 是噪声底，不是效应量。
> ⑥ **跨进程双峰格给区间不给单点**：A bs=128 `gc=3 bf16` = **1.35 / 1.74ms 双峰**（轮内 σ=1%），不进任何正文分母（方法论 26）。

## 1. 主张（一句话）与它的三条腿

> 在 CPU+GPU 异构上跑 MoE：热专家常驻 GPU、冷专家走 CPU int8/AVX2，**两条腿重叠**，
> 每帧延迟 ≈ `max(CPU 腿, GPU 腿) + 固定串行主机开销`。这台机器上可测量的每一项都按这个模型付钱。

| # | 这条腿被谁证明 | 最硬的一个数 |
|---|---|---|
| ① **模型本身成立** | 乙-1 / P0-②（`delay=3ms` 把 CPU 腿按死后，打 CPU 腿的刀全部变平） | **重叠的价格 16/16 格为正**：+8.5%~+67.6%（gemm A 档随 bs 单调涨） |
| ② **代价结构成立（两堵墙）** | T8/T14/乙-2 + P0-②③④a | CPU 字节墙 49us/专家(gemm 2MB)~63us(swiglu 2.53MB)@42GB/s、算力墙 7us/slot@288GMAC/s、**交叉点≈5 slot/专家**；GPU skinny 标定 **250GB/s** |
| ③ **收益可分解、可归因** | LADDER 14 刀 + 乙-1/乙-2/乙-2b/乙-2c + P0-①②③④a | A/d0 **1.758 → 0.300ms（−82.9%）**、C/d0 **6.109 → 0.756ms（−87.6%）**；decode 下的 −60~−76% 全来自主机侧串行 |

**对外可引用的倍数**（P0-②，A 放对、同机、玩具权重那张表是唯一合法来源）：
swiglu bs=128 **vs 纯CPU 5.47x / vs 纯GPU 1.51x**、bs=32 2.61x / 1.40x；gemm bs=128 4.18x / 1.25x。
🚨 **倍数必须连着 bs 一起报**：bs=4 只有 1.11~1.63x，bs=1 是纯 CPU 赢（异质在 decode 下不给力）。
🚨 外部模型爱写的那句"CPU 延迟 3ms 时 3.5x 加速"实测是 **1.0x**。

**真权重 + 三方交换上最硬的三格**（P0-④a/④a附，显存报**稳态**，基准 = **同 dtype** 的 gc=0）：

| 格 | 基准 gc=0 | 换到 | 峰值/稳态 MB | p50 | KL(P‖Q) | 买到什么 |
|---|---|---|---|---|---|---|
| bs=1 放对 bf16 | 0.273ms / 0.1MB / 4.928e-03 | gc=3 | 111.4 / **65.9** | **0.215ms** | **1.353e-05** | 花 66MB ⇒ 快 21.2% **且** 质量好 364x |
| bs=32 放对 bf16 | 1.378ms / 0.3MB / 2.841e-04 | gc=5 | 186.1 / **110.0** | **0.390ms** | **1.180e-05** | 花 110MB ⇒ 快 71.7% **且** 质量好 24x |
| bs=128 放对 bf16 | 3.536→0.510 / 3.427→0.493 | gc=7 | 262.1 / **155.3** | **0.510 / 0.493ms** | **1.532e-06** | 花 155MB ⇒ 快 **85.6%（两轮同值）** 且质量好 66x |
