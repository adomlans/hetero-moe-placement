# blog3 · 真形状与 bf16 —— 换到真权重上哪些结论活着，以及两笔分开付的钱

> **写作红线（四篇共用，贴在页眉）**：
> ① **一阶量与二阶量两列并报**："误差 <1%" 不许单独成句（L2 差 11.6x 时 KL 差 303x，gc=0→1 那一格两列方向相反）。
> ② **质量只报相对量 + 必附参照行**：换成 8 选 2 fp32 稠密 MoE 本身就值 KL 1.897e-01(bs=32) / 8.854e-02(bs=128) ⇒ 比引擎最狠那档贵 **668x / 871x**。
> ③ **显存必须写明峰值 MB 还是稳态 MB**：gc=5 峰值两档同为 186.1MB，稳态才是 169.3(fp32) vs 109.8(bf16)。
> ④ **三方交换只用 P0-④a 两张归档**；每个数字指回一张用户自跑的判决表。
> ⑤ **配对段 Δ 只认【配对可用】✓ 行**；✗ 行的 Δ 是噪声底。
> ⑥ **跨进程双峰格给区间不给单点**（A bs=128 `gc=3 bf16` = 1.35 / 1.74ms）。

## 0. 一句话

前 14 刀全部是在**玩具形状**（D=1024 / N=2048、`randn` std=1 权重、seed 造的 A/C 两档）上量的。
P0-① 把它们搬到 **SmolLM-135M 真权重 + 真激活**（D=576 / N=1536、路由=embed、x=第 8 层 MLP 入口）上重跑，
结论分成三类：**活下来的**、**价签变了的**、**被玩具形状藏起来的 bug**。这一篇讲这三类，
再讲真形状上掉出来的两笔新账：**降精的价**（−16% → −53%，随 gc 涨）和**量化的两笔钱**（int8 比 bf16 贵 **274~364x**）。

| 玩具上的结论 | 真权重上 | 依据（全部用户自跑） |
|---|---|---|
| 前 14 刀的收益 | ✅ **一刀没被推翻**：⓪T4 基线落后 **+110%~+648%** | P0-① 四通路 |
| CPU 字节墙 42GB/s | ✅ 同一公式，只是每专家字节变了：**2.53MB ⇒ 63us/专家** | P0-① |
| 工作集挤不挤 L3 | ✅ 反而**变宽松**：每专家 6.00→**2.53MB**（0.42x），CPU 常驻 3 个 = **7.6MB < L3 12MB**（玩具只能 1 个） | 同上 |
| 命中偏斜 | 🆕 **不是 seed 造的，是量出来的**：`[42.3, 13.2, 17.7, 6.8, 1.4, 12.6, 6.0, 0.1]`，最热/最冷 **433x** | 同上 |
| 精度四笔 | 🚨 **变贵且贵在新地方**：h 再量化 **+1.94pp**（玩具 +0.44pp） | 同上 |
| fp16 会溢出 | 🚨 **玩具专属**：真权重 max\|h\|=**13.6** 不溢出（玩具 **223 个 inf/nan**） | 同上 |
| 逐位对拍全绿 | 🚨 **玩具形状藏雷**：D=1024 整除 ⇒ 无尾巴块 ⇒ 越界读看不见 | 红线 H |
| "异质一定赢" | 🚨 **bs=1 两个配置都被纯 CPU 打败**（−20.8% / −13.9%）——**范围已收窄**：这条只在**稠密 GPU 腿**下成立；GPU 腿按真流量读权重后 bs=1 反而快纯 CPU **−34.1%**（乙-2d） | P0-① 四通路 + 乙-2d |

## 1. 真分布改了谁：路由、命中、和 h 那一笔

**换激活 = 换被测对象**（P0-① bs=1 C 同一格换三种激活，路由也跟着换）：

| 换进去的激活 | 整条 relRMSE | CPU 腿 slot |
|---|---|---|
| 真激活（第 8 层 MLP 入口） | **7.2267%** | 2 |
| 同尺度高斯 | 4.9813% | 1 |
| std=1 玩具 | 0.0001% | **0** |

std=1 玩具把路由打成"全进 GPU"，CPU 腿 **0 个 slot** ⇒ "量化误差"直接归零。
**玩具不是简化，是把被测对象删掉了。** 这也是 `①异质` 那一行在玩具激活下 relRMSE=0.0001% 的全部来历。

**精度四笔**（只量 CPU 腿那 2 个 slot，分母=该实例 CPU 腿的 fp32 真值 rms=0.796）：

| 笔 | 真权重（SmolLM-135M） | 玩具对照列 |
|---|---|---|
| ① 只量化 W | relRMSE **4.4110%** | 2.03% |
| ② 再加 x 量化 | 5.2886%（**+0.88pp**） | +0.29pp |
| ③ 再加 h 再量化 | 7.2267%（**+1.94pp**） | +0.44pp |
| ④ kernel 实测 | 7.2267%（④vs③ 绝对 **5.16e-06**，相对 4.6e-07 ⇒ ≤1 LSB 级） | — |

⇒ 三笔里没有一笔是"再降 W 精度"能省的：**真分布把 h（swiglu 中间量再量化）放大约 3.6x**，
它现在是 CPU 腿误差的**唯一大头**。想再省字节，先给 h 上更细的格点（每 128 一组），别碰 W。
顺带把 fp16 的疑问关掉：真权重 max\|g\|=5.92 / max\|u\|=6.2 / max\|h\|=**13.6**，离 65504 远得很 ⇒
**候选只剩 bf16 是因为工程上不想再管一套溢出边界，不是因为 fp16 会炸。**

## 2. 降精的价：随 gc 涨到 −53%，但**永远不是 2 倍**

先在**玩具形状**（`bench_dtype` 就是 D=1024/N=2048）上把"字节 ÷2 时间 ÷2"这句话杀掉（乙-2c，bs=1、gc=5、
同 seed 逐位可比、配对 **5/5 轮更快**）：

| 档位（裸端到端） | GPU 字节/帧 | GPU 半边 | 有效带宽 | 端到端 |
|---|---|---|---|---|
| gemm fp32 → bf16 | 40 → **20MB** | 0.179 → 0.144（**−19.6%**） | 235 → **146GB/s** | **−15.4%** |
| swiglu fp32 → bf16 | 120 → **60MB** | 0.473 → 0.290（**−38.8%**） | 266 → 217GB/s | **−33.9%** |

字节正好减半、时间只减三分之一到五分之一 ⇒ **半精 kernel 在 skinny GEMV 上没拿到满带宽**。
（机制解释靠归因探针：大块 `gu` 档 −49% 满兑现、`down` 档每张只 4MB 起步就没带宽、
pre+D2H 图那 **≈0.05ms** 不随 dtype 变 —— 探针是模型自跑，**不进记录**，正文的价全在下一张表。）

**降精真正的价在 P0-④a 的配对段**（真形状真激活、同 gc 两档同时常驻 + 单双号换序；只列【配对可用】✓ 行）：

| bs | 配置 | gc | p50 fp32 → bf16 | 配对Δ | 更快轮 | 稳态省MB |
|---|---|---|---|---|---|---|
| 1 | A | 3 / 5 / 7 / 8 | 0.257→0.215 / 0.321→0.262 / 0.395→0.300 / 0.431→0.312 | −16.3 / −18.3 / −24.1 / **−27.5%** | 7/7 ×4 | 35.4 / 59.6 / 84.6 / 95.5 |
| 32 | A | 5 / 7 / 8 | 0.511→0.396 / 0.693→0.351 / 0.743→0.354 | −22.5 / −49.3 / **−52.4%** | 7/7 ×3 | 59.6 / 84.6 / 95.5 |
| 128 | A（主） | 5 / 7 / 8 | 0.761→0.700 / 1.021→0.482 / 1.097→0.567 | −8.1 / **−52.8** / **−48.3%** | 7/7 ×3 | 59.6 / 84.6 / 95.5 |
| 128 | A（附） | 7 / 8 | 1.036→0.491 / 1.101→0.571 | **−52.6 / −48.2%** | 7/7 | 84.6 / 95.5 |
| 128 | C（主/附） | 8 | 1.098→0.571 / 1.154→0.594 | **−48.0 / −48.5%** | 7/7 | 95.5 |

一条单调线读出来很清楚：**降精的兑现率 = GPU 半边有没有成为关键路径。**

- bs=1（CPU 腿和固定串行成本还在关键路径上）：−16%~−27%；
- bs≥32 且 gc≥7（CPU 腿几乎被搬空，GPU 半边就是关键路径）：**−48%~−53%**，两轮凭据差 ≤0.5pp；
- gc≤5 的大 bs 格子（CPU 腿还有 22~234 个 slot）**连效应量都算不上** —— 30 行配对只有 15 行 ✓，
  其余 ✗ 行里最贵的一次误读是 A bs=128 `gc=3` 的 **+29.9%（逐轮中位 −1.2%、更快轮 5/7）**，
  它在附轮变成 −19.3%：**同一格两轮给出符号相反的 Δ，就是噪声底的直接示证。**

⇒ 允许写的句子："在这台机器上，当放置把 GPU 半边推成关键路径时，bf16 换来 **−48%~−53%** 帧时与
**85~96MB** 稳态显存；在 bs=1 只值 −16%~−27%。"
🚨 禁止写："降精 = 2 倍 / bf16 一定快一倍"—— 字节确实减半，时间从来没有。

## 3. 两笔钱：CPU 腿 int8 与 GPU 腿 bf16，**各独占一整行**

拆分不是拟合出来的，是靠**零流量没有数值入口**拿到的：`gc=0` 时 GPU 腿 **0 个 slot**（闸门⑤：换 dtype 逐位 0），
`gc≥3` 放对时 CPU 腿 **0 个 slot**。于是同一张表里有两行分别是"纯 int8 的代价"和"纯 bf16 的代价"：

| bs | CPU 腿 int8（gc=0） | GPU 腿 bf16（CPU 腿 0 slot） | L2 比 | **KL 比** |
|---|---|---|---|---|
| 1 | L2 7.2267% / KL **4.928e-03** / TV 3.912e-02 | 0.7862% / **1.353e-05** / 2.060e-03 | 9.2x | **364x** |
| 32 | 5.9174% / **2.841e-04** / 5.967e-03 | 0.5121% / **9.376e-07** / 3.914e-04 | 11.6x | **303x** |
| 128 | 5.5114% / **1.016e-04** / 3.384e-03 | 0.4929% / **3.705e-07** / 2.250e-04 | 11.2x | **274x** |

（bf16 那列取 CPU 腿 0 slot 的格子：bs=1 的 `gc=3/5/7/8` 四档 KL **逐位相同** 1.353e-05；bs=32/128 取 `gc=8`。）

三件事同时成立，才是这一节真正的结论：

1. **int8 那笔比 bf16 贵 274~364x**（二阶量），而一阶量只差 **9~12x** ⇒ 一阶量完全看不见这笔钱的量级（blog1 §3）。
2. **bf16 在 token 级几乎免费**：bs=128 整张表 12 格里，换 bf16 只让 `gc=5` 那一格的 top-1 从 100.00 → 99.22
   —— **128 个 token 里翻了 1 个**，而那一格的分辨率本来就是 0.78pp。
3. **ΔNLL / ppl 全表是噪声**：引擎所有档 |ΔNLL| ≤ **2.743e-03**、ppl 比落在 **[0.9973, 1.0023]** 且有正有负；
   而参照行（换成 MoE 本身）是 ΔNLL **+1.378e-01**(bs=32) / **+5.290e-02**(bs=128)，比最狠的引擎档还大 **50x**。
   ⇒ **P0-③ 判决⑥**：质量段不许出现 ppl，"int8 让 ppl 变好了"这种句子一句都不许写。

两个读表纪律：① 配对段里的 `KL比(other/主)` 出现 **2.2e+05** 这种数，全是 fp32 那档本来就 ≈1e-11 的格子，
**分母趋零的比不读**，要读就读绝对 KL（bs=128 的 bf16 = 3.705e-07）；② 所有 KL 都是相对量 ——
参照行比引擎最狠那档贵 **668x(bs=32) / 871x(bs=128)**，别把本表的 KL 当 ppl 用（红线②）。

## 4. 显存两列与帕累托：bf16 是前沿的主要股东

两列口径不能混（红线③）：**峰值 MB** = 窗口高水位−空载（含建图/暖机的 **fp32 staging**，所以降精**不动它**：
bs=1 `gc=5` 两档峰值同为 186.1MB）；**稳态 MB** = 暖机后仍驻留（降精只在这列看得见：169.3 → **109.8**）。
权重算式 fp32 **10.1** / bf16 **5.1** / int8 **2.53** MB每专家；两列都比算式大 = `wcat` + 死 bmm 副本 + 图静态缓冲，不是 bug。
闸门⑤ 那行 `峰值列之后额外高水位 +92~94MB` 是 **fp32 裁判自己**的 CPU 腿权重副本（`(E−gc)×10.1MB`），**不是引擎成本**。

帕累托前沿（延迟↓ / 稳态显存↓ / KL↓ 三者都不被支配，平手带 2%）：

| 格 | 前沿点数 | 被支配（白付钱） | 读法 |
|---|---|---|---|
| bs=1 A | 4（`0fp32 1bf16 3fp32 3bf16`） | 8 点 | 前沿缩回 `gc≤3`：**bs=1 时 GPU 半边不值钱**（blog2 §4） |
| bs=32 A | 7 | `0fp32 1bf16 3fp32 5fp32 7fp32` | 前沿 7 点里 **5 个是 bf16**；被支配 5 点里 **4 个是 fp32** |
| bs=128 A | 10 | **只有 `5fp32` `7fp32`**（两轮逐字相同） | fp32 在同等 KL 下占更多显存 ⇒ 被支配 |
| bs=128 C | 主 8 / 附 7 | 主 `1fp32 3fp32 5fp32 7fp32`；附多一个 **`5bf16`** | **唯一跨进程不稳的前沿格 = `gc=5 bf16`**：双峰 2.257 / 3.282 直接把它推进被支配 |

⇒ "降精是可选优化"这个说法在这里不成立：**fp32 的两档在放对的大 bs 上直接掉出前沿。**
🚨 引用显存必须点名是哪一列，且前沿集合本身在双峰格上是**进程级**性质，不是配置性质。

## 5. 本项目的三格主张（fig2 的三条绿线，引用请按这个写法）

基准 = **同 dtype 的 `gc=0`**（纯 CPU 下界），显存报**稳态**：

| 格（放对 bf16） | p50 | 稳态 MB | KL(P‖Q) | 一句话 |
|---|---|---|---|---|
| bs=1 `gc=0 → 3` | 0.273 → **0.215** | 0.1 → **65.9** | 4.928e-03 → **1.353e-05** | 花 66MB ⇒ 快 **21.2%** 且质量好 **364x** |
| bs=32 `gc=0 → 5` | 1.378 → **0.390** | 0.3 → **110.0** | 2.841e-04 → **1.180e-05** | 花 110MB ⇒ 快 **71.7%** 且质量好 **24x** |
| bs=128 `gc=0 → 7` | 3.536→**0.510** / 3.427→**0.493** | 1.0 → **155.3** | 1.016e-04 → **1.532e-06** | 花 155MB ⇒ 快 **−85.6%（两轮同值）** 且质量好 **66x** |

三条绿线的**机制是同一句话**：`gc↑` 把 slot 从 int8 腿搬到 bf16 腿，KL 掉两个数量级；
时间是副产品（blog2 的两堵墙决定它什么时候才真的省）。
引用纪律：① bs=128 端点必须**两份凭据一起交**（主表 3.536→0.510、附轮 3.427→0.493）；
② 不引用 A bs=128 `gc=3 bf16` 的绝对 p50（双峰 **1.35 / 1.74ms**）；
③ 放错档的欠给只报 **fp32 侧 +101~106%**，bf16 侧那两次 297%/472% 的单点数不许进正文。

## 6. 顺带标价的第三笔：零流量专家每帧照付（详表在 blog2 §6）

bs=1 放对 `gc=3 → gc=8` 两档**流量完全相同**（GPU 腿都 2 slot、CPU 腿都 0 slot），
p50 fp32 **0.257 → 0.434**、bf16 **0.215 → 0.317** ⇒ **每多驻一个零流量专家付 35us(fp32) / 20us(bf16)**，
多驻 5 个付 **69% / 47% 的帧时买 0 个命中**。同一格降精的 Δ 是 **−16.1%（7/7 轮，逐位数值不动）**
⇒ 这笔钱**可回收的量级探针**已经到手（乙-2d 目标 ÷2~÷2.5），而它同时也是**规则账本与实测对不上**的根源。
